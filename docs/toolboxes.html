Toolboxes

The built-in tools — FilePreview, ImportData, PyEditor and JupyterLab — and how to use them.

Toolboxes

Toolboxes are the built-in tools that ship with MedICS. Each opens as a tab in the central area — from the Toolboxes menu, from the activity bar, or by double-clicking a supported file in File Explorer.

ToolboxWhat it is for
FilePreviewRead-only preview of images, volumes, tables, Markdown and code.
ImportDataLoad raw stacks, image sequences, DICOM, NIfTI, MAT/NumPy and video into the workspace.
PyEditorA Python editor and terminal that run against the live workspace.
JupyterLabThe full JupyterLab UI in a tab, running MedICS's own Python environment.

FilePreview

Preview any file without changing it: 2-D images, DICOM and NIfTI volumes, TIFF stacks, tables (CSV, TSV, Excel, Parquet), Markdown, and source code. For image and volume views you can move through slices, adjust window/level, zoom and pan, and apply flips, rotations and transposes.

Opening a file

  • Double-click a file in the File Explorer — non-text files open here.
  • Right-click a file and choose Open (or Open in FilePreview for a text file).
  • Drag & drop one or more files onto the window from the operating system or the Explorer.
  • Click Open… (Ctrl+O) on the toolbar and pick one or more files.
  • Drop a variable from the Variables panel to preview data that is only in memory.

Each file opens in its own inner tab. Re-opening a file just activates its tab; the Welcome tab comes back when every file tab is closed.

ImportData

Load images and volumes into the workspace. Choose how the source is structured, let the importer read and preview it, then send the result to the workspace. Imported data appears in the Variables panel.

Data type

ModeUse it for
Volume DataA single volume read from a raw/binary stack file or a container (.mat, .npy, .npz, NIfTI, DICOM, video).
Image SequenceA folder or a set of image files stacked into one volume, in file-name order.

The parameters below the selector change with the mode.

Volume Data parameters

FieldWhat it sets
Image typeThe pixel type of the raw file — 8-bit, 16-bit Signed, 16-bit Unsigned, 32-bit Signed/Unsigned, 16/32/64-bit Real, 24-bit RGB/BGR, 32-bit ARGB/ABGR or 1-bit Bitmap.
Width / HeightThe size of one frame, in pixels.
FrameThe number of frames in the stack.
Offset to first ImageBytes to skip at the start of the file before the first frame (for a header).
Gap Between ImagesBytes to skip between consecutive frames.
permutationHow the three axes are ordered in the file (for example 0,1,2).
Read OrderF (Fortran), C or A — how the file's bytes fill the array.
Color OrderAABBCC (planar) or ABCABC (interleaved) for colour data.
Little-endian byte orderTick when the file's bytes are little-endian.
Import formatThe dimension order written to the workspace — DHWC (Depth, Height, Width, Channel) or HWCD.
Keep C for gray imageKeep the channel axis even for a grayscale image.
Horizontal / Vertical FlipMirror the volume as it is read.

NIfTI, DICOM, MAT, NumPy and video files are read automatically; the raw parameters above apply to undecorated binary stacks.

What you can import

  • Image sequences — folders or sets of TIFF, PNG, JPEG and similar frames.
  • Volume files — DICOM (.dcm/.dicom), NIfTI (.nii/.nii.gz).
  • Containers — MATLAB .mat, NumPy .npy/.npz and MedICS .med files.
  • Video — .mp4, .avi and similar load as a stack of frames.
  • Raw/binary stacks — any file read with the Volume Data parameters above.

Drag & drop

Drop files or a folder anywhere on the window. Several image files (or a folder) are treated as an image sequence; a single volume file is opened as Volume Data.

Status bar

The green status bar along the bottom reports progress and messages ("File loaded successfully!", "N files found in the folder"), the pointer pixel readout, and — for a raw stack — a byte-match badge that confirms the header/offset settings add up ("✔ All bytes matched").

PyEditor

A Python editor in a tab, with syntax highlighting, code completion, an integrated terminal and a set of code-navigation tools. Run (F5) executes your script against the live console, so it can use the variables already in your workspace.

Toolbar & tabs

SaveCtrl+SSave the active tab; an untitled tab asks for a path first.
Run in JupyterF5Run the selection — or the whole file when nothing is selected — in the Jupyter console.

Each file is a tab; a modified tab shows a *. Save As… (Ctrl+Shift+S) writes to a new path. Right-click a tab for Close Tab, Close Other Tabs, Close All Tabs and New Tab; a breadcrumb bar above the editor shows the file's folder path, and Ctrl+` toggles the terminal.

The References panel opens when you run Find All References. It lists the symbol, line and file; double-click a row to open that file at that line. Breadcrumbs above the editor also let you walk up and down the file's structure.

Running code

Press F5 (or click Run in Jupyter) to run the selected text, or the whole file when nothing is selected. The code runs in the Jupyter console at the bottom of the window, so it sees the same workspace variables you do; the output appears in that console. A per-selection run is also bound to F9.

Integrated terminal

Ctrl+` shows or hides the terminal — a real shell inside a tab. The + New Terminal button starts another one; a shell picker offers Command Prompt, PowerShell, Windows PowerShell and Git Bash. Each terminal row in the list has buttons to Clear or Kill it, and right-clicking the list gives Rename, Kill Terminal and Clear. The terminal is a shell for convenience — use the Jupyter console when you want your workspace variables.

Reviewing agent edits

When the AI assistant changes a file you have open, PyEditor shows the changes inline with a small toolbar — ↑ / ↓ move between changes, and Accept, Reject, Accept All and Reject All keep or undo them.

JupyterLab

The full JupyterLab interface, embedded in a tab. It runs on MedICS's own Python environment, your workspace is available inside notebooks as ws, and it needs no setup — notebooks, completions and the debugger work out of the box. Install it into MedICS's environment to enable the tab (see Get started).

The two environments

When you start a new notebook or console from the Launcher, two environments are on offer:

EnvironmentWhat it runs
MedICS (this environment)The default. The same Python interpreter as MedICS itself, so every package MedICS uses is already importable. It is wired into the live application: your workspace is available as ws, and the familiar scientific names (NumPy, Matplotlib and friends) are ready to use — the same starting point as the Jupyter console. Figures render inline. Variables you create here appear in the Variables panel.
Python 3 (ipykernel)A plain Python kernel, with none of the MedICS additions. Notebooks started here still run in the same interpreter, but there is no ws bridge and no pre-loaded MedICS namespace — use it when you want an untouched kernel, or as a fallback.

Because the default is MedICS (this environment), a notebook behaves like the rest of MedICS: a volume you load in MedICS is visible in the notebook, and a variable created in a notebook shows up in the Variables panel. To switch, open the notebook's Kernel → Change Kernel menu and pick the other environment. Your notebooks are saved under the MedICS home folder and reopen with the tab.
